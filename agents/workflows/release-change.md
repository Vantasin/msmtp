# Release Change

Use this workflow when the repository starts publishing stable snapshots,
release notes, or tagged operating baselines.

1. Confirm the repository state is documented accurately.
2. Review recent meaningful changes for inclusion in
   [CHANGELOG.md](../../CHANGELOG.md).
3. Run a drift review if the release includes structural or workflow changes.
4. Publish any release notes or tags using the repository's chosen release
   process once such a process exists.
